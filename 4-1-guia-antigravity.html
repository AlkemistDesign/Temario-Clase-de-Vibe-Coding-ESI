Google Antigravity para Developers

Delega una funcionalidad sin perder el control

Durante bastante tiempo, programar con IA consistía en abrir un chat, pedir una función, copiarla en tu editor y probar si funcionaba. Con agentes la situación cambia: puedes encargar una tarea, dejar que analice el proyecto, decida archivos, proponga un plan, modifique código y ejecute pruebas. Pero cuanto más trabajo ejecuta un agente, más importante es que tengas claro qué le delegas, dónde debe parar y qué vas a revisar.

💡
La regla de oro: El agente ejecuta. Tú sigues dirigiendo. La autonomía del agente tiene sentido cuando no convierte el resultado en una caja negra.
1

Antes de delegar, haz que el agente pare y te enseñe el Plan

Abre en Antigravity IDE un proyecto pequeño que conozcas. Si no entiendes el repositorio, te va a costar mucho saber si el agente lo ha hecho bien.

  • Planning Mode: El agente analiza primero el trabajo y prepara un Implementation Plan antes de empezar a modificar código.
  • Request Review: Cuando el agente llegue a un punto de control, se detendrá a pedir aprobación en lugar de continuar directamente.
  • Fast Mode: Úsalo solo para tareas simples y muy localizadas (ej. renombrar una variable). Para funcionalidades completas, mantén el plan.
2

Encárgale una tarea, no le tires una frase

Si pides simplemente "Añade un buscador a mi aplicación", dejas en el aire decisiones críticas: ¿sobre qué campo busca?, ¿distingue mayúsculas?, ¿qué pasa si está vacío?, ¿puede instalar librerías?, ¿requiere tests? Encárgale una tarea con 4 piezas estructuradas: objetivo, contexto, restricciones y criterios de aceptación.

Prompt · Delegación Estructurada en Antigravity 
Quiero añadir búsqueda por título a la lista de tareas existente.

Antes de modificar código:
1. Analiza cómo funciona actualmente la lista de tareas y su filtrado.
2. Identifica los archivos que sería necesario modificar.
3. Prepara un Implementation Plan.
4. No implementes ningún cambio hasta que revise el plan.

Restricciones:
- Mantén el stack y la arquitectura actuales.
- No añadas dependencias nuevas salvo que sean realmente necesarias y me expliques por qué.
- No modifiques funcionalidades que no estén relacionadas con esta tarea.

Consideraré la tarea terminada cuando:
- La búsqueda se realice por título.
- Ignore mayúsculas y minúsculas.
- Elimine espacios al principio y al final de la consulta.
- Si la consulta está vacía, se muestren todas las tareas.
- Existan tests para estos comportamientos.
3

Antes de pulsar Proceed, lee lo que piensa hacer

No pases el Implementation Plan como quien acepta cookies. Audítalo con criterio comprobando estos 5 puntos antes de autorizar la ejecución:

1. Comprensión: ¿Ha entendido el objetivo real de la tarea?
2. Scope de archivos: ¿Va a tocar únicamente los archivos necesarios?
3. Arquitectura: ¿Respeta las convenciones y patrones del proyecto?
4. Complejidad: ¿Intenta meter dependencias o abstracciones innecesarias?
5. Verificación: ¿Cómo piensa comprobar que la implementación funciona?

"Un agente rápido ejecutando un mal plan sigue ejecutando un mal plan (y te hace perder el doble de tiempo)."

4

Ahora sí: Deja que el agente implemente

El agente modificará los archivos, utilizará el terminal y ejecutará pruebas. Tú sabes por qué existe cada cambio porque los criterios estaban fijados de antemano.

// Código inicial
export function filterTasks(tasks, query) {
  return tasks.filter(task => 
    task.title.includes(query)
  );
}
// Resultado según criterios
export function filterTasks(tasks, query) {
  const normalizedQuery = query.trim().toLowerCase();
  if (!normalizedQuery) {
    return tasks;
  }
  return tasks.filter(task =>
    task.title.toLowerCase().includes(normalizedQuery)
  );
}
5

Review Changes: Revísalo como si fuese un Pull Request

Abre el panel Review Changes para recorrer los diffs. Aplica esta regla: si no aprobarías ese cambio en una revisión hecha por otra persona, tampoco lo apruebes porque lo haya hecho un agente.

Prompt · Pedir explicación paso a paso sin tocar código 
Explícame este cambio paso a paso sin modificar nada.

Quiero entender:
- ¿Qué problema resuelve cada cambio?
- ¿Por qué has elegido esta solución?
- ¿Qué alternativas había?
- ¿Qué riesgos tiene?
- ¿Y qué podría romperse?
6

Que los tests estén en verde no cierra la tarea

Los tests solo comprueban aquello que alguien decidió comprobar. Si te has olvidado de un caso límite (ej. strings con solo espacios, títulos repetidos, regresiones), la suite estará verde y seguirás teniendo un bug.

Prompt · Verificación final y casos límite 
Antes de cerrar la tarea:
1. Ejecuta las pruebas relacionadas.
2. Busca casos límite que no hayamos contemplado.
3. Comprueba si el cambio puede haber provocado alguna regresión.
4. Resume cualquier riesgo que siga abierto.

No realices nuevos cambios sin indicármelo primero.
7

La última palabra sigue siendo tuya

El ciclo completo de desarrollo profesional con agentes se resume en 6 fases continuas:

1. Define
Objetivos y límites
2. Planifica
Propuesta del agente
3. Revisa
Auditar el plan
4. Delega
Ejecución acordada
5. Valida
Tests y diffs
6. Decide
Aprobación final
