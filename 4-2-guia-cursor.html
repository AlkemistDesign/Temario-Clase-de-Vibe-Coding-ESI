Cursor para Programar con IA

Avanza más rápido sin dejar de entender lo que estás construyendo

Abres un proyecto que apenas conoces, le pides al agente que modifique cosas y esperas a ver qué ocurre. El problema llega después, cuando tienes diez archivos cambiados y no sabes qué ha cambiado ni por qué. Esta guía enseña a abrir un repositorio, entender cómo funciona, realizar un cambio pequeño y acotado con IA y revisar el resultado antes de aceptarlo.

💡
Principio clave: Deja que Cursor te quite trabajo, no criterio. Úsalo para entender mejor el proyecto, acotar el cambio, revisar el plan y validar lo que ha hecho antes de aceptarlo.
1

¿Qué es Cursor y por qué tantos developers lo están usando?

Basado en VS Code, Cursor mantiene todo lo familiar (explorador, terminal, extensiones), pero integra la IA con contexto completo de tu proyecto. No es solo un chat: busca archivos, comprende cómo se relacionan entre ellos y realiza cambios directos sobre el árbol de código.

Esto evita el constante viaje de ida y vuelta a ChatGPT copiando trozos descontextualizados. Pero cuanto más contexto y capacidad de actuación le das a la IA, más criterio necesitas tú para dirigirla.

2

Entiende el proyecto antes de cambiar código

En lugar de pedir código de inmediato o abrir carpetas a ciegas, utiliza Cursor para investigar el proyecto y construir tu primer mapa mental:

Prompt · Mapeo de Arquitectura y Módulos en Cursor 
Explícame cómo está organizado este proyecto antes de modificar nada.

Quiero entender:
1. Cuál es el punto de entrada.
2. Qué carpetas y módulos son los más importantes.
3. Cómo se relacionan entre ellos.
4. Dónde está la lógica principal.
5. Qué archivos debería revisar primero para entender el proyecto.

No modifiques ningún archivo.

Consejo: Cuando Cursor te señale los archivos clave, ábrelos, léelos y verifica que lo que te cuenta coincide con el código real.

3

Empieza por un cambio pequeño que puedas revisar

No pidas a Cursor que cambie media aplicación de golpe. Cuanto mayor sea el cambio, más difícil será comprobar si ha tomado buenas decisiones arquitectónicas. Comienza por una tarea acotada:

Prompt · Tarea Acotada con Restricciones Claras 
Quiero evitar que una tarea pueda guardarse sin título.

Antes de modificar código:
Revisa cómo se crean actualmente las tareas e identifica qué archivos intervienen en ese proceso.

El cambio debe cumplir estas condiciones:
1. No se puede guardar una tarea si el título está vacío.
2. Tampoco si únicamente contiene espacios.
3. Mantén la arquitectura y las tecnologías actuales.
4. No modifiques otras funcionalidades que no estén relacionadas con esta tarea.

Antes de implementar nada, explícame brevemente cómo lo harías.
4

Plan Mode en Cursor: Revisa antes de tocar código

Desde el campo de entrada del agente, pulsa Shift + Tab para activar Plan Mode. Cursor analizará el proyecto, formulará preguntas aclaratorias y preparará un plan antes de generar código.

1. ¿Objetivo claro? ¿Ha entendido qué resultado esperas?
2. ¿Archivos justos? ¿Toca solo los archivos necesarios?
3. ¿Arquitectura? ¿Respeta los patrones del repo?
4. ¿Tests y pruebas? ¿Cómo comprobará que funciona?
5

Deja que implemente y audita los cambios

Usa Diff View para ver cambios archivo a archivo y Review Changes para revisar el conjunto global antes de aceptar. Si encuentras algo que no entiendes, pídele explicaciones:

Prompt · Auditoría de Diff y Evaluación de Riesgos 
Explícame estos cambios antes de que los acepte.

Quiero entender:
1. Qué has modificado y por qué.
2. Qué alternativas había.
3. Qué riesgos tiene esta solución.
4. Qué podría romperse.

No realices nuevos cambios todavía.
