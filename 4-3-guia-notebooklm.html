Guía de NotebookLM para Developers

Prepara el contexto antes de programar con IA

Generar código antes de entender qué quieres construir es la receta más rápida para crear deuda técnica. Si pides a un agente "Implementa recuperación de contraseña", quedan docenas de decisiones en el aire (caducidad del token, invalidación de sesiones, seguridad, emails). NotebookLM se coloca un paso antes: para reunir especificaciones, entender qué sabes, detectar vacíos y llegar a tu agente con instrucciones precisas.

💡
El flujo fundamental: No uses NotebookLM para escribir código, sino para construir la ficha de contexto. 1. Pregunta → 2. Localiza → 3. Comprueba → 4. Decide.
1

Crea un Notebook para el problema concreto

No crees un cuaderno general llamado "Proyecto" o "Programación". Céntralo en una funcionalidad específica, como por ejemplo: "Proyecto — Recuperación de contraseña". Un espacio acotado evita el ruido contextual.

2

No metas más contexto: mete MEJOR contexto

No subas 30 archivos por si acaso. Selecciona fuentes con un propósito definido:

1. Especificación: Requisitos y comportamiento esperado.
2. README / Stack: Configuración y tecnologías vigentes.
3. Arquitectura: Patrones, convenciones y módulos afectados.
4. Docs Oficiales: Proveedor de autenticación / emails.
5. Seguridad: Políticas de tokens, expiración y sesiones.
3

Las 5 Preguntas Clave antes de programar

Pregunta 1 · Objetivo Exacto

¿Qué tenemos que construir exactamente?

"Basándote únicamente en las fuentes de este Notebook, explícame qué comportamiento debe tener esta funcionalidad para considerarse terminada. Indica qué fuente respalda cada requisito importante."

Pregunta 2 · Restricciones

¿Qué restricciones debes respetar?

"Identifica las restricciones técnicas, de arquitectura, seguridad, compatibilidad o negocio que podrían condicionar la implementación de esta funcionalidad. Indica de qué fuente sale cada una."

Pregunta 3 · Ubicación en el sistema

¿Dónde encaja dentro del proyecto?

"Según la arquitectura y la documentación disponibles, ¿qué componentes del sistema podrían verse afectados por esta funcionalidad? Señala también qué decisiones técnicas existentes deberíamos respetar."

Pregunta 4 · Detección de vacíos y contradicciones

¿Qué te falta por saber? (Punto crítico)

"Busca información que todavía no esté definida: ambigüedades, contradicciones entre fuentes o decisiones que deberíamos aclarar antes de comenzar a implementar. No inventes una respuesta cuando las fuentes no permitan resolverla."

Pregunta 5 · Criterios de aceptación

¿Cómo sabes que está terminado?

"Extrae de las fuentes los criterios de aceptación, comportamientos esperados y casos límite que deberíamos comprobar antes de considerar terminada la funcionalidad."

4

Genera la Ficha de Contexto para tu Agente

Una vez auditadas las respuestas y las citas en las fuentes originales, lanza este prompt final en NotebookLM para empaquetar el contexto que le entregarás a tu agente de desarrollo (Antigravity, Cursor, etc.):

Prompt · Generación de Ficha de Contexto Estructurada 
Basándote únicamente en las fuentes que hemos revisado, prepara una ficha de contexto para implementar esta funcionalidad con un agente de desarrollo.

Incluye:
- Objetivo de la funcionalidad
- Comportamiento esperado
- Componentes del proyecto que podrían verse afectados
- Restricciones técnicas y de arquitectura
- Decisiones existentes que debemos respetar
- Requisitos de seguridad, si existen
- Casos límite
- Criterios de aceptación
- Cuestiones que todavía no estén resueltas

No escribas código. No inventes información que no aparezca en las fuentes y señala cualquier punto que necesitemos aclarar antes de desarrollar.
